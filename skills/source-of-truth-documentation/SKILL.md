# 事实源驱动的技术文档

## 可信度顺序

优先级通常是：可复现运行结果与当前代码 → 版本化配置/迁移 → 自动生成的接口描述 → 已验证的外部规范 → 人工手册/旧文档 → 记忆和推测。低优先级资料只能补充，不能覆盖高优先级事实。

## 写作流程

1. 明确读者需要做的决策或操作，而非先罗列模块。
2. 从实际入口、调用关系、配置与测试抽取当前行为。
3. 用外部资料解释术语、约束和背景；提取质量差或无法验证的内容要标注待确认。
4. 把“为什么这样设计”、边界条件、失败行为和已知限制写入文档。
5. 代码或配置改动后，审查受影响的文档段落；过期的版本说明、示例和命令同样需要更新。

## 审查清单

- 每个关键事实是否能回链到当前来源？
- 是否区分已实现、计划中、已废弃和未知？
- 是否避免把假设、一次性测试或旧版本结论写成常态？
- 文档中的接口、命令和时序承诺能否真正执行或验证？

## 输出

标注事实来源、版本范围和未确认项；让读者能复现结论，而不是只能相信文字。
