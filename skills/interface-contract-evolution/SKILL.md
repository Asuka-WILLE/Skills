# 接口契约演进

## 接口不是字段列表

一个稳定接口同时包含字段名、类型、单位/编码、空值语义、顺序/一致性、错误语义、版本与性能预期。任意一项变化都可能破坏消费者。

## 变更流程

1. 清点生产者、消费者、存储、日志、监控、测试样本和人工使用者。
2. 写出旧契约与新契约，并逐项标注兼容、废弃或破坏性变化。
3. 为新字段定义默认/缺失语义；为删除或改义的字段定义迁移窗口和失败策略。
4. 需要渐进发布时，使用版本字段、双读、兼容回退或双写；避免让不同版本静默误读。
5. 对逻辑上成组的数据定义一致性边界：部分成功时整体丢弃、标记不完整或携带版本，绝不拼接不同周期的旧值。
6. 让生产端和所有受影响消费端在同一变更计划中验证。

## 验收

| 样本 | 预期 |
| --- | --- |
| 旧生产者 → 新消费者 | 有明确兼容行为 |
| 新生产者 → 旧消费者 | 按策略安全降级或明确拒绝 |
| 新生产者 → 新消费者 | 类型、单位、空值和展示一致 |
| 部分/失败数据 | 不产生看似正确的混合结果 |

## 输出

交付一份契约差异、发布顺序、回滚方案和互操作验证结果。
