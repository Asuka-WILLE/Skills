# 产物与依赖卫生

## 分类优先

在删除、忽略、重新生成或替换任何文件之前，按以下类别分类：

1. 源代码和版本化配置：项目事实源，默认保留。
2. 可再生构建产物、缓存和临时文件：可清理，但应先确认生成命令。
3. 本机/个人状态：通常不提交，可能影响本地体验。
4. 依赖锁定与供应商代码：是否能重建取决于版本、校验和许可证，不能想当然删除。
5. 验收证据和诊断日志：必要时移到仓库外归档，而非混在源码里。

## 工作流

1. 检查版本控制状态、忽略规则、构建脚本和依赖清单。
2. 对每个候选文件说明：谁生成、能否重建、删除风险、是否已被追踪。
3. 依赖/工具链故障先复现最早的具体错误，核对版本和导出接口；不要先猜权限或重装所有东西。
4. 清理时只处理明确、已核实的单一路径；不使用宽泛递归删除或模糊通配符。
5. 清理后通过干净环境构建或最小健康检查验证恢复能力。

## 输出

列出“保留 / 可重建 / 待确认 / 外部归档”四类清单及其理由，并记录恢复命令。
