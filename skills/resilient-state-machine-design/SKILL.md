# 韧性状态机设计

## 先画状态，不先写 if

列出正常、初始化、降级、失败、恢复中的状态，以及每个状态的进入条件、退出条件、允许动作和可观察输出。状态和副作用分开：状态标志本身不会停止任务、撤销权限或关闭资源。

## 设计规则

1. 对每个异常输入定义安全默认值；不要让“最后一次成功状态”无限期延续。
2. 区分事件触发与状态持续：如果事件不再到来，超时/轮询路径仍必须能驱动安全动作。
3. 将检测结果明确映射到执行动作，并确保该动作位于每轮都可达的路径上。
4. 将一次性动作设计为幂等，例如重复取消、停止、关闭或发零值不会产生额外伤害。
5. 恢复必须有证据：可信输入、依赖恢复、资源准备或人工确认；禁止仅因收到一个事件就恢复危险操作。
6. 对状态转换记录原因、时间和关联请求，方便事后调试。

## 必测转换

- 正常 → 异常：动作真的触发。
- 异常期间无新事件：安全状态仍保持或刷新。
- 异常 → 恢复：未满足恢复条件时被拒绝。
- 重复异常与重复恢复：不重复执行副作用。
- 部分失败：不混合旧状态和新状态。

## 交付

提供状态表、转换图、每个转换的副作用和测试证据；避免只给一串嵌套条件。
