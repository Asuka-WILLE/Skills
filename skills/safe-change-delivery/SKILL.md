# 安全交付变更

## 原则

交付的单位是经过审阅、可追溯、可回滚的一组相关改动，不是“当前工作区里所有文件”。

## 交付前

1. 核对当前分支、目标分支、远端地址、共同基线与工作区状态。
2. 对每个改动回答：它是否属于这次目标？是否包含生成物、个人配置、凭据或其他人的未完成工作？
3. 审阅差异和暂存区，按逻辑拆成最小提交；每个提交可构建、可测试、可解释。
4. 在提交信息中写清行为改变和验证范围，避免“fix stuff”。

## 交付与核验

1. 先运行适当验证，再提交和推送。
2. 推送后核对本地提交、目标远端引用、CI/构建状态和目标环境版本。
3. 对锁、冲突或权限错误，先确认具体原因和活动进程；只做最小、可恢复的修复，禁止用清空工作区解决。
4. 如果基线变化，重新审阅再合并，不能假设远端仍与开始时相同。

## 输出

```text
基线与目标：
纳入/排除的改动：
验证：
提交与远端核验：
回滚方式：
```
